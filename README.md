# Мини-CRM для учёта клиентов и сделок (Вариант А)

Веб-приложение (Full-Stack) для управления клиентской базой, ведения сделок по воронке продаж, фиксации заметок и аналитики сумм по статусам.

---

## 1. Архитектура и принятые решения

Приложение построено по клиент-серверной архитектуре (REST API + SPA):

* **Frontend (клиентская часть):** HTML5, CSS3 (Bootstrap 5) и нативный JavaScript (Fetch API). Использование Bootstrap обеспечивает адаптивную вёрстку как для десктопных, так и для мобильных экранов.
* **Backend (серверная часть):** Python + фреймворк **FastAPI**. Обеспечивает высокую скорость работы, автоматическую валидацию входящих данных (Pydantic) и интерактивную документацию Swagger (`/docs`).
* **База данных:** **MS SQL Server** (управление через SSMS 22) + **SQLAlchemy ORM** (драйвер `pyodbc`). ORM позволяет безопасно работать с таблицами и защищает от SQL-инъекций.
* **Безопасность и права доступа:**
  * Пароли хранятся в БД исключительно в виде криптографического хеша (`bcrypt`).
  * Аутентификация реализована через **JWT-токены** (Bearer Token).
  * Разграничение прав: роль **Менеджер (`manager`)** видит и редактирует только своих клиентов и сделки; роль **Администратор (`admin`)** видит общую базу всей компании и имеет права на удаление записей.

## 2. Схема базы данных (`crm_db`)

База данных состоит из 4 связанных таблиц:

1. **`users` (Пользователи)**
   * `id` (PK, Integer) — уникальный идентификатор
   * `username` (String, Unique) — логин пользователя
   * `password_hash` (String) — хеш пароля
   * `role` (String) — роль (`admin` или `manager`)

2. **`clients` (Клиенты)**
   * `id` (PK, Integer) — уникальный идентификатор
   * `name` (String) — имя или ФИО клиента
   * `phone` (String) — контактный телефон
   * `email` (String, Nullable) — электронная почта
   * `company` (String, Nullable) — название компании
   * `owner_id` (FK -> `users.id`) — ответственный менеджер

3. **`deals` (Сделки)**
   * `id` (PK, Integer) — уникальный идентификатор
   * `title` (String) — название сделки
   * `amount` (Float) — сумма сделки в рублях
   * `status` (String) — этап воронки (`new`, `in_progress`, `won`, `lost`)
   * `client_id` (FK -> `clients.id`) — клиент, к которому привязана сделка
   * `manager_id` (FK -> `users.id`) — ответственный менеджер

4. **`notes` (Заметки к сделкам)**
   * `id` (PK, Integer) — уникальный идентификатор
   * `content` (Text) — текст комментария/заметки
   * `created_at` (DateTime) — дата и время создания
   * `deal_id` (FK -> `deals.id`) — сделка, к которой оставлена заметка
   * `author_id` (FK -> `users.id`) — автор заметки

**Связи между таблицами:**
* Один `User` может вести много `Client` и `Deal` (1:N).
* У одного `Client` может быть много `Deal` (1:N).
* К одной `Deal` может быть прикреплено много `Note` (1:N).

## 3. Инструкция по запуску

### Шаг 1. Подготовка базы данных
1. Откройте **SSMS 22** и подключитесь к локальному экземпляру MS SQL Server.
2. Создайте пустую базу данных с именем `crm_db`.
3. При необходимости укажите имя вашего сервера в переменной `SERVER_NAME` в файле `backend/database.py`.

### Шаг 2. Установка зависимостей и запуск сервера
Откройте терминал в корневой папке проекта и выполните команды:
```bash
pip install -r requirements.txt
cd backend
python -m uvicorn main:app --reload
```
Сервер запустится по адресу `http://127.0.0.1:8000` (таблицы в базе данных создадутся автоматически при первом запуске). Документация API доступна по адресу `http://127.0.0`.

### Шаг 3. Запуск клиентской части
Откройте файл `frontend/index.html` в любом современном браузере.
